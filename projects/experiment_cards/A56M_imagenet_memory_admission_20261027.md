# A56M ImageNet 真实显存资格计量（规划，尚未实现GPU入口）

## 问题与目的

2026-10-27用户提供的队列采样：GPU0 free6026MiB，GPU1 free10785MiB；
两卡有其他进程工作，A56 ImageNet门槛12288MiB始终不满足。该门槛是工程值，
不是已测峰值。FFHQ12例已完成，不再阻塞其独立报告。

可否定假设：在当前冻结ImageNet256模型、float32、batch1、原30点及原算子下，
实际单例训练和当前方向反向的峰值，可能低于12GiB准入值；须真实测量而非直接降阈值。
这属于A56资源资格子步骤，不是新的质量方法或第六个探索方向。

## 固定项与有限预算

从冻结A56计划的第一个ImageNet SR案例读取图、配置和种子；不按GT或可见画质换图。
两条路径均使用原30点：一次原优化unroll（num_epochs=1，仅显存计量，不能当原300调用质量基线）
和一次U方向unroll；原算子/FP32/精度政策/checkpoint/input-only VJP机制不变。
最多60个中心前向，外加t319/t14原实际VJP计量各6探针，共最多72诊断前向、32输入VJP。
原ζ/D损失反向、checkpoint内部重算、算子调用另列，不能混作输入VJP或免费开销。
若真实执行结构不满足此预算，先修订计量卡并展示新预算，不运行超限部分。
没有GT质量评价、参数选择、优化轮数收益或NFE节省结论。

记录每条路径peak allocated/reserved、模型加载后/调用前free、耗时、实际调用数、OOM位置；
任何OOM保留失败成本并停止该实现，不重复撞显存、不终止其他人的进程。
必须先让现有队列在明确无worker时保存状态并交接，防止同卡重复抢占和同目录写入。
计量用独立目录，不写原案例attempt，也不把计量张量混入原A56质量数据。

## 决策分支

1. 两条路径均通过且峰值加至少1GiB余量小于可分配空间：新增独立资源准入适配器，
   保持原全部科学源不动，先运行唯一固定原300调用案例并核对所有原门控，再继续剩余案例。
   72次计量成本额外列出，不隐匿到原9624预算内。
2. 显存仍不足：只保留一种内存策略候选——原反向保存张量CPU卸载，保持FP32和数学目标。
   它需要单独的真实模型输出/VJP等价门控与成本记录；没有原实现可配对参考时不得声称已等价。
   通过之前不做八例大规模重建；不静默fp16、降分辨率、换checkpoint或换样本。
3. 所需显存/可用设备仍不满足，或等价门控失败：ImageNet记resource_limited/incomplete；
   原FFHQ结论照常报告，论文不写“多数据集已经成立”。FFHQ结果不得反向调原ImageNet冻结规则。

本卡是待实现队列设计；当前唯一已交付可运行的新入口是CPU FFHQ readout。
不把计划、CPU回归或OOM未触发当作真实ImageNet资格通过。
